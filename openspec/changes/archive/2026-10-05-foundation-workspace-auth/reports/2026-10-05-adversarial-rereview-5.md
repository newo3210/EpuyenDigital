Two Major issues still block archive. Both are about secrets, which D14 says must be strict ("secrets are masked in every realistic format"):

- **U-1 (Major, regression)**: the narrowed T-4 skip rule only skips before a *strict* inner key (`token|secret|passw(or)d|api[_-]?key`). After a word ending in `key`, a secret pair whose key is `service_key`, `secret_key`, `private_key` or one of the new keys `session` and `credential` now leaks its value **whole**. For example, `missing key: service_key: abc123secret` → `missing key=[redacted] abc123secret`. The spec says "a secret pair SHALL still be found after a word ending in `key`", and it lists `service_key` as an example key. `0a77033` masked `service_key` and `secret_key` in this position.
- **U-2 (Major, pre-existing spec/code mismatch)**: the spec sentence rewritten in `c0a7674` (and `design.md` J-2) says secret keys are those "**containing** `token`, `secret`, or `passw`". The code only matches keys that **end** in those words. `password_confirmation=…`, `{"passwordHash":"…"}`, `refresh_token_hash: '…'` and `accessTokenValue` leak whole. `ARCHITECTURE_SDD.md` says "ends in", so the root doc and the spec contradict each other.

Both have cheap fixes (U-1: widen the strict inner-key list to keys ending in `[_-]key` plus `session`/`credential`/`cookie`/`authorization`; U-2: either allow a bounded suffix after the key word, or narrow the spec and design to "ending in"). Minors U-3..U-5 and nits U-6, U-7 are listed below.
