### Things I attacked that held up

Listed only because each mitigates a documented risk:
- **Direct RPC.** `anon` and `authenticated` get `42501 permission denied` both in psql and through PostgREST (`/rest/v1/rpc/insert_client_error_report` with the anon key and with the operator's access token). `proacl = {postgres=X, service_role=X}`, `PUBLIC` holds nothing, the function is `security invoker` with `search_path = ''`, and every table reference is schema-qualified.
- **SQL injection.** All parameters are bound values in static SQL. A `trace_id` and `message` containing `'); drop table …; --` were stored verbatim.
- **Origin flip.** An admin updating `origin` in either direction, or together with `status`, gets `P0001 forbidden_column` (guard `:33-40`). pgTAP `006:140-147` covers support.
- **Server logging.** A service-role insert without `origin` gets `'server'`, so `logServerError` is unaffected. Server rows never count toward the client limit (pgTAP `006:99-116`).
- **Lock semantics.** The transaction-scoped lock is released at commit. `lock_timeout = 8s` on `authenticator` turns a pathological wait into an RPC error, which becomes `failed`, then 500, with nothing stored (fails closed). A 64-bit hash collision only adds serialization and cannot bypass the limit.
- **Flow order.** Auth (401), then the advisory count (429, body unread), then `readBody` (413), then schema, then trace, then redaction, then the atomic store (`report-error.ts:41-74`). A unit test asserts that `readBody` runs before the store.
- **Backfill.** Only rows with `details->>'origin' = 'client'` are flipped, and the key is removed. Older truncated rows default to `server`, which only matters inside a 60 s window that has long passed.
- **Redaction performance.** 20 new adversarial 16 KB inputs aimed at `QUOTED_VALUE`, `JSON_SECRET_RE` (escape runs, unclosed values, backslash pairs), `SECRET_KEY` prefix runs and the DNI lookarounds. Worst case **36.6 ms** (`1234567.` repeated), well under 200 ms. No catastrophic backtracking.
- **Control cases.** Dates (`2026-10-05`, `05.10.2026`), dotted IPs and the decimals listed in the tests stay intact (but see R-1 for the cost of that choice).
- **N-8 edges.** Leap days, 2000-01-01 and 2100-12-31 are kept, and the regex guarantees a numeric year.
