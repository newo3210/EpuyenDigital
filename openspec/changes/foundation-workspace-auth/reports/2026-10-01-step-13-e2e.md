## Defect found and fixed: digest correlation

- **Observed (13.7c):** the detail panel showed `"digest": "[phone]"`. Next error digests are numeric strings; the redactor masks them as phone numbers, so the client report and the server row could not be matched — contradicting design D8.
- **Fix (spec first):** design D8 updated, then `features/errors/digest-ref.ts` added (TDD). Both `report-error` and `request-error` now store `details.digestRef` — the first 16 hex chars of `sha256(digest)` re-encoded as letters `a`–`p`, which redaction never alters; the raw digest is no longer stored.
- **Re-run:** after restarting the dev server, triggering the same failure produced:

```
   code   | source | route_type |    digest_ref    | raw_digest
----------+--------+------------+------------------+------------
 853DEA22 | web    | render     | fhiodldnnlnjmckc | f      ← server row (onRequestError)
 5F233DCD | web    |            | fhiodldnnlnjmckc | f      ← client report (code shown to the user)
```

- **Dev-only note:** on the first re-run without restarting, only the client row appeared. `instrumentation.ts` dynamically imports the edited module and Turbopack's hot reload did not refresh it; after a dev-server restart the server row was written again. Not reproducible on a fresh server; production builds have no hot reload.
